# Анкета «Питание жителей Нарына»

Веб-приложение для онлайн-анкетирования взрослых жителей города Нарын (Кыргызстан).
Рассчитано в первую очередь на заполнение с телефона, в том числе пожилыми людьми:
один вопрос на экран, крупные кнопки, фиксированная нижняя панель, два языка и три темы.

Ответы сохраняются в Google Таблицу через serverless-функцию на Vercel.
Ключи Google находятся только на сервере, в клиентский код они не попадают.

## Стек

- Vite + React 18 + TypeScript, собственный CSS на переменных (без UI-фреймворков);
- свой лёгкий словарь переводов (`src/i18n/ru.ts`, `src/i18n/ky.ts`);
- одна serverless-функция `api/submit.ts` (Node.js runtime): пишет в таблицу
  через Apps Script либо через сервисный аккаунт (`googleapis`);
- тесты на Vitest.

## Структура

```
api/submit.ts          приём анкеты и запись строки в Google Таблицу
apps-script/Submit.gs  запись в таблицу без Google Cloud (вариант 1)
src/survey/config.ts   декларативное описание всех экранов и переходов
src/survey/flatten.ts  сборка строки таблицы (названия столбцов и значения — на русском)
src/survey/validate.ts проверка ответов перед переходом
src/survey/storage.ts  сохранение прогресса в localStorage
src/components/        шапка с прогрессом-хребтом, варианты ответа, нижняя панель
src/i18n/              словари ru / ky и провайдер перевода
```

### Как добавить или изменить вопрос

1. Добавьте тексты в `src/i18n/ru.ts` (кыргызский перевод в `src/i18n/ky.ts` обязателен —
   TypeScript не даст собрать проект с неполным словарём).
2. Добавьте экран в массив `SCREENS` в `src/survey/config.ts`, указав тип
   (`single`, `multi`, `number`, `meal`, `foodYesNo`, `foodFrequency`, `measures`),
   название столбца таблицы и при необходимости условие показа `when`.
3. Проверьте тесты: `npm test`.

В компонентах нет текстов на русском — всё берётся из словарей по ключам.
**В таблицу ответы всегда пишутся по-русски**, по ключу варианта, независимо от языка
интерфейса, поэтому данные с двух языков анализируются вместе. Язык заполнения
записывается в отдельный столбец «Язык анкеты» (`ru` / `ky`).

## Языки и темы

- Переключатель RU / KY в шапке на каждом экране, выбор сохраняется в `localStorage`.
- Параметр адреса задаёт язык для QR-кодов: `?lang=ky`, `?lang=ru`.
- Тема: светлая / тёмная / как в системе. Применяется в `<head>` до первой отрисовки,
  поэтому при загрузке нет мигания.

Кыргызский перевод в `src/i18n/ky.ts` помечен комментарием `TODO: проверить носителем языка`.

## Подключение к Google Таблице

Есть два способа, оба бесплатные. Функция `api/submit.ts` сама выбирает нужный:
если задана переменная `APPS_SCRIPT_URL`, работает первый вариант, иначе второй.
Формат строки в таблице у них одинаковый.

### Вариант 1 (рекомендуемый): Apps Script, без Google Cloud

Писать в таблицу будет её собственный скрипт. Проект в Google Cloud, сервисный
аккаунт и JSON-ключ не нужны.

1. Откройте нужную Google Таблицу → **Расширения → Apps Script**.
2. Создайте файл `Submit.gs` и скопируйте в него содержимое `apps-script/Submit.gs`
   из этого репозитория.
3. В начале файла замените значение `SECRET` на свою длинную случайную строку.
   Сгенерировать можно так:

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('base64url').replace(/[^A-Za-z0-9]/g,''))"
   ```

   Используйте только латинские буквы и цифры. Символ `$` в файле `.env` означает
   подстановку другой переменной, поэтому секрет с `$` обрежется по первому такому
   символу, и скрипт ответит `forbidden`.

4. **Развернуть → Новое развёртывание → тип «Веб-приложение»**:
   - «Запуск от имени» — **От моего имени**;
   - «У кого есть доступ» — **У всех**.

   При первом развёртывании Google попросит разрешить скрипту доступ к таблице —
   это нормально, экран с предупреждением проходится через «Дополнительно →
   Перейти к проекту».
5. Скопируйте адрес вида `https://script.google.com/macros/s/.../exec` и задайте
   переменные окружения:

   | Переменная | Значение |
   | --- | --- |
   | `APPS_SCRIPT_URL` | адрес развёрнутого веб-приложения |
   | `APPS_SCRIPT_SECRET` | та же строка, что в `SECRET` внутри `Submit.gs` |

Адрес веб-приложения знает только серверная функция — в браузер он не попадает,
поэтому посторонний не сможет писать в таблицу напрямую. После каждого изменения
кода в Apps Script нужно делать **новое развёртывание** (или «Изменить
развёртывание → Новая версия»), иначе продолжит работать прежняя версия.

### Вариант 2: сервисный аккаунт Google

Чуть больше шагов на старте, зато всё остаётся внутри одного проекта на Vercel.
Sheets API тарифицируется бесплатно, биллинг и карта для него не нужны.

1. [console.cloud.google.com](https://console.cloud.google.com/) → создайте проект.
2. **APIs & Services → Library → Google Sheets API → Enable**.
3. **APIs & Services → Credentials → Create credentials → Service account**
   (роли на уровне проекта не нужны).
4. Откройте созданный аккаунт → **Keys → Add key → Create new key → JSON**.
5. В таблице нажмите **Поделиться** и добавьте адрес из `client_email`
   с правами **Редактор**. Без этого шага API вернёт 403.
6. Задайте переменные окружения:

   | Переменная | Значение |
   | --- | --- |
   | `GOOGLE_SERVICE_ACCOUNT_EMAIL` | `client_email` из JSON-ключа |
   | `GOOGLE_PRIVATE_KEY` | `private_key` из JSON-ключа, переводы строк в виде `\n` |
   | `GOOGLE_SHEET_ID` | ID таблицы из её адреса `/spreadsheets/d/<ID>/edit` |
   | `SHEET_NAME` | название листа, по умолчанию `Ответы` |

`GOOGLE_PRIVATE_KEY` вставляйте целиком, вместе со строками `-----BEGIN PRIVATE KEY-----`
и `-----END PRIVATE KEY-----`, переводы строк должны остаться как `\n`. Ошибка
`error:1E08010C:DECODER routines::unsupported` в логах означает именно неверный
формат ключа, а не нехватку прав.

### Где задавать переменные

Локально — файл `.env.local` в корне проекта (образец в `.env.example`).
На Vercel — **Project → Settings → Environment Variables**, для окружений
Production, Preview и Development. После добавления нужен повторный деплой.

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # подставьте свои значения
npm run dev                  # http://localhost:5173
```

`npm run dev` поднимает и анкету, и `/api/submit`: функция `api/submit.ts` подключена
к dev-серверу Vite (плагин `localApi` в `vite.config.ts`) и читает переменные из
`.env.local`. Отдельный `vercel dev` для разработки не нужен, но если хочется
проверить всё ровно в том же окружении, что на production:

```bash
npx vercel login && npx vercel link
npx vercel dev
```

Быстрая проверка записи в таблицу:

```bash
curl -s -X POST http://localhost:5173/api/submit \
  -H 'Content-Type: application/json' \
  -d '{"lang":"ru","durationMin":1,"answers":[["1. Пол","Мужской"]]}'
```

Ожидаемый ответ — `{"ok":true,"number":"Н-0001"}`, и в таблице появляется строка.
Тестовые строки потом удалите: номер анкеты считается по номеру строки.

Чтобы открыть анкету на телефоне в той же сети: `npm run dev -- --host`.

Проверки:

```bash
npm test          # юнит-тесты (flatten, переходы 16 → 18 и 21 → 23, словари)
npm run build     # типы и production-сборка
```

## Развёртывание

```bash
npx vercel link    # один раз: привязать папку к проекту Vercel
npx vercel --prod  # сборка и публикация
```

Либо подключите репозиторий в интерфейсе Vercel — фреймворк определится как Vite,
папка сборки `dist`, функция `api/submit.ts` развернётся автоматически.
После деплоя не забудьте задать переменные окружения и сделать повторный деплой.

## Как устроена таблица

Одна анкета — одна строка листа «Ответы». Шапка создаётся при первой анкете:

```
№ анкеты | Дата и время | Язык анкеты | Время заполнения, мин | 1. Пол | 2. Возраст | …
```

- «Дата и время» — по часовому поясу Asia/Bishkek;
- номер анкеты — порядковый, вида `Н-0001`;
- если в анкете появились новые столбцы, они дописываются в конец шапки,
  а строка раскладывается по названиям столбцов, а не по позиции;
- несколько ответов записываются через «; », вариант «Другое» — как `Другое: <текст>`;
- пропущенные по логике вопросы — «Не применимо», «Не знаю» в числовых вопросах — словами;
- дробные числа пишутся с запятой.

## Защита

- принимаются только POST-запросы;
- тело ограничено 100 КБ, значения — 5000 символов;
- значения, начинающиеся с `=`, `+`, `-`, `@`, экранируются апострофом (защита от формул);
- скрытое поле-ловушка отсекает ботов;
- простое ограничение частоты по IP (20 анкет за 10 минут на инстанс функции);
- в варианте с Apps Script его адрес и общий секрет известны только серверной
  функции, в браузер они не попадают;
- в ответах об ошибках нет деталей ключей и сообщений Google API — они только в логах Vercel.

## Если отправка не проходит

Ответ `/api/submit` показывает, на каком шаге всё остановилось:

| Ответ | Что значит | Что делать |
| --- | --- | --- |
| `{"ok":true,"number":"Н-0001"}` | строка записана | — |
| `not_configured` | не заданы ни `APPS_SCRIPT_URL`, ни переменные сервисного аккаунта | задать переменные и сделать повторный деплой (`npx vercel env ls` покажет, что уже есть) |
| `upstream_rejected` | скрипт ответил `forbidden` — не совпал секрет | сверить `APPS_SCRIPT_SECRET` и `SECRET` в `Submit.gs`, затем развернуть **новую версию** скрипта |
| `upstream_error` | адрес отвечает, но не тем — обычно доступ к веб-приложению не «у всех» или ссылка ведёт на `/dev` | проверить настройки развёртывания и что адрес заканчивается на `/exec` |
| `server_error` | ошибка самого Google API в варианте с сервисным аккаунтом | посмотреть логи: `npx vercel logs <адрес>` |

Локально то же самое видно сразу при старте `npm run dev` — строка
`→ /api/submit: …` говорит, какой способ записи подхватился из `.env`.

## Режим интервьюера

Прогресс сохраняется в `localStorage`: при возврате анкета предлагает «Продолжить»
или «Начать заново». После отправки показывается экран благодарности с кнопкой
«Новая анкета» — удобно, когда один планшет передают от респондента к респонденту.
Если отправка не удалась, ответы остаются на месте и кнопку можно нажать ещё раз.

## Доступность

Настоящие `input[type=radio]` и `input[type=checkbox]`, видимый фокус, контраст AA,
учёт `prefers-reduced-motion` и safe-area на iPhone, вся анкета помещается
по ширине в 360 px.

## Файл Code.gs

`Code.gs` остался от предыдущей версии анкеты, которая целиком жила в Google Apps Script.
Для этого проекта он не нужен: в варианте 1 запись делает `apps-script/Submit.gs`,
в варианте 2 — `api/submit.ts`. Формат столбцов у всех трёх совместим.
